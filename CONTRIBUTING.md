# Contributing to HART

Thank you for your interest in contributing! Because this project is in an early, highly opinionated stage of development, I have strict guidelines for contributions. My goal is to prevent you from wasting your valuable time writing code that might not get merged.

## Ask before you code

Before writing any code, **you must open an Issue** detailing the bug you want to fix or the feature you want to add.

- Wait for me to explicitly approve the Issue and assign it to you.
- If you submit a PR for a feature or refactor that was not discussed beforehand, it will be closed.

## AI Usage Policy

As mentioned in the README, the core of this project (like the emulator) is entirely hand-written.

- **No Pure AI PRs:** I do not accept pull requests that are purely AI-generated or "vibecoded."
- **Take Ownership:** If you use an AI assistant (like Copilot or Claude) to help write your code, you are still strictly responsible for understanding _every single line_ you submit.
- **Idiomatic Code:** The code must match the existing project style and be idiomatically correct. If a PR looks like an unedited LLM dump, it will be rejected.

## Quality Standards

1. **Scope:** Keep PRs small and focused on a single Issue.
2. **Commit Messages:** Write clear, descriptive commit messages. Use [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/).
3. **No Unrelated Changes:** Do not bundle random refactors, formatting changes, or dependency

## Review Process

Since I am maintaining this solo, and am a full time student, PR reviews might take some time. I reserve the right to respectfully decline a PR if I feel it adds too much maintenance burden or diverges from the project's long-term vision.
