# HART (frontend)

The desktop GUI for [HART](../README.md): a **Tauri 2 + SvelteKit 5 + Tailwind 4**
app that wraps the [Haskell RISC-V emulator](../emulator/README.md) into an
interactive assembler and time-travel debugger.

## Commands

Run from `frontend/` with **pnpm**:

```bash
pnpm build-sidecar   # build the emulator and copy it into src-tauri/binaries
pnpm tauri dev       # run the full app (Vite + Rust shell + sidecar)
pnpm tauri build     # produce native installers
pnpm check           # type-check Svelte + TS
pnpm lint            # eslint
```

> Run `pnpm build-sidecar` once before your first `pnpm tauri dev`, and again
> after any emulator change, `tauri dev` spawns the prebuilt sidecar and won't
> rebuild it for you.

## How it fits together

```
┌─────────────────────┐   send_command (stdin)   ┌──────────────────┐
│   Svelte SPA (UI)   │ ───────────────────────▶ │  Rust/Tauri core │
│  Monaco · xterm ·   │                          │   (main.rs)      │
│  registers · memory │ ◀─────────────────────── │  supervises &    │
└─────────────────────┘  "emulator-update" event │  bridges stdio   │
                                                 └────────┬─────────┘
                                  line-delimited JSON     │ over stdio
                                                 ┌────────▼─────────┐
                                                 │  hart-emulator   │
                                                 │   --rpc sidecar  │
                                                 └──────────────────┘
```

- **UI → emulator:** `sendToHaskell(command, data?)` (`src/lib/util.ts`) encodes
  `{ command, data }`; Rust's `send_command` writes it to the sidecar's stdin.
- **emulator → UI:** Rust reads the sidecar's stdout line by line and re-emits
  each response as a Tauri `"emulator-update"` event (or `"sidecar-exit"` if it
  dies).
- **UI listener:** `cpuStore.initListener()` handles those events and is the
  single source of truth for CPU state.

## Type bindings

`src/bindings/*.ts` are **generated by ts-rs** from `src-tauri/src/types.rs`. Change the Rust structs/enums and regenerate. The `#[serde(rename = …)]` attributes map Rust snake_case to the camelCase JSON the
emulator emits, so the Rust types, the generated TS, and the emulator's output
all have to agree.

## State stores

Svelte 5 runes, as class singletons in `src/lib/store/*.svelte.ts`:

| Store            | Responsibility                                                             |
| ---------------- | -------------------------------------------------------------------------- |
| `cpuStore`       | CPU state, source map, and all emulator commands; tracks loaded-vs-edited. |
| `fileStore`      | Open editor files, open/save, unsaved-changes tracking.                    |
| `terminalStore`  | Two consoles: `system` (build/status log) and `program` (emulator stdout). |
| `extensionStore` | The ISA extension catalogue and which ones are enabled.                    |
| `logStore`       | The structured system-console log.                                         |
| `layoutStore`    | Pane visibility/refs and the global HEX/DEC toggle.                        |

Keyboard shortcuts live in `src/lib/keymap.svelte.ts`; editor syntax colors in
`src/lib/editor/`.

## UI composition

`src/routes/+page.svelte` is the root. Components live under `src/components/`:

- **`toolbar/`**: compile + transport controls, file open/save, panel/theme and
  ISA-extension menus, HEX/DEC toggle.
- **`ide/`**: `Editor` (tabs + `Monaco`) and the xterm-based terminal.
- **`debug/`**: CPU header, register/CSR files, and the virtualized memory view,
  in resizable Paneforge panes.
